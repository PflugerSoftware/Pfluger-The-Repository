# Pfluger AI Adoption & ROI Dashboard

A self-contained HTML dashboard built from a **Claude.ai organization data export**, made to shape an **ROI / investment conversation** for firm leadership and to tie AI usage to the architectural **scope of work** (Pre-Design → Design → CD → CA).

Built 2026-06-11. Data window: Jan 9 – Jun 11, 2026 (577 conversations, 8,095 messages, 44 of 100 people onboarded).

---

## TL;DR for a new agent

- The deliverable is **`index.html`** — open it in a browser. It is fully self-contained (data embedded, charts hand-rolled in inline SVG, **no CDN / no internet needed**), so it can be emailed or dropped on SharePoint.
- It is **generated**, not hand-edited. Two Node scripts produce it:
  1. `process.js` reads the raw export → writes `dashboard_data.json` (aggregates + classification).
  2. `build.js` injects that JSON into `index_template.html` → writes `index.html`.
- **Never edit `index.html` directly.** Edit `index_template.html` (layout/charts/ROI logic) or `process.js` (data/classification), then re-run the build.
- Environment: **Node** (built on v22). This folder has its own `package.json` with `"type":"commonjs"` to override the parent repo's `"type":"module"` — needed so the scripts can use `require()`.

## Files

| File | Role | Edit it? |
|---|---|---|
| `index.html` | **The dashboard.** Open this. Self-contained, shareable. | No — regenerated by `build.js` |
| `index_template.html` | Source: layout, CSS, all charts, ROI model, forecast logic. Contains `const DATA = /*__DATA__*/{};` placeholder. | Yes — for visuals/model |
| `process.js` | Reads the export, classifies every conversation (topic + scope phase), aggregates, writes `dashboard_data.json`. | Yes — for data/inputs/taxonomy |

| `package.json` | Forces CommonJS scope in this folder. | No |
| `data-*-batch-*/` | The **raw Claude.ai org export** (source data: `conversations.json`, `users.json`, `projects/`, etc.). | No |

## How to rebuild / update with a NEW export

Prereqs: Node installed.

1. **Get a fresh export:** Claude.ai → Organization settings → export org data. Download and **unzip**.
2. **Drop it in:** copy the unzipped `data-…-batch-0000` folder into this directory. Remove the old one (`process.js` auto-detects the `data-*-batch-*` folder, so keep **only one**).
3. **Update the inputs** at the top of `process.js` (clearly marked `EDIT THESE EACH EXPORT`):
   - `onboarding` — cumulative people onboarded per **past** month (actuals).
   - `rampFuture` — projected cumulative people per **future** month (drives the forecast/projection lines).
   - `TARGET_HEADCOUNT` — full-firm target (currently 100).
4. **Build:**
   ```
   node process.js
   node build.js
   ```
5. Open `index.html`.

### What updates automatically vs. what you set
- **Auto (from the data):** all totals, daily/monthly trends, topic & phase classification, per-account breakdowns, human/assistant split, and the **partial-last-month run-rate** (computed from the export's last date via `lastMonthPartial`, so the “Today” marker and June-style extrapolation self-adjust).
- **You set (in `process.js`):** the onboarding ramp, future ramp, and target headcount — these come from HR/rollout, not the export.

## How the dashboard is organized (tabs)

1. **Overview** — hero cards (messages, top-2-themes share, people onboarded, ROI multiple) + the projected message-activity chart + two donuts (scope-of-work phases, themes).
2. **Trends** — monthly messages stacked by theme; total monthly; fastest-growing themes.
3. **By Account** — one card per seat, with a canonical-ordered topic chip set.
4. **Themes** — themes ranked by conversations and by depth (msgs/chat) + narrative.
5. **Scope of Work** — the Pre-Design → Design → CD → CA flow, themes mapped into each phase; Practice/Personal shown off-arc.
6. **ROI** — live sliders (hourly value, time multiplier, seat cost) drive a transparent value-of-time-saved model.
7. **Forecast** — onboarding ramp vs. message volume, projected to 100 users and through December.

## Key modeling decisions (and where they live)

All of the following are in **`index_template.html`** unless noted.

- **Two independent classifiers** (in `process.js`): `TOPICS` (what they talk about) and `PHASES` (scope of work). Each conversation is scored against keyword lists; the best match wins. Same conversation can be e.g. theme=Code, phase=CD. ~97% of text-bearing chats match; the rest fall to "General / Other".
- **Empty / API conversations:** ~35% of conversations (≈2,800 messages) have **no exported text** — these are API / Claude Code / agent "cowork" sessions. They count toward totals, are shown as their own category, and are **excluded from the topic mix**. This is surfaced honestly, not hidden.
- **ROI value model:** `TIER` object = minutes **saved per conversation**, tiered by research depth (e.g. Submittals/QA ≈ 45 min, Code ≈ 38, Revit ≈ 23, Personal = 0). These were rebased ×1.5 from an original draft so a submittal review reflects a ~4× speedup (an hour of work done in ~15 min). Value = chats × minutes ÷ 60 × multiplier × hourly rate.
- **ROI slider defaults:** hourly `$150` (`s-rate`), multiplier `1.0×` (`s-mult`), seat cost `$20` (`s-seat`). NOTE: actual firm AI bill is ~$400/month total (≈$9/seat), so the seat-cost model **understates** ROI — a future improvement is to switch the cost input to a flat monthly bill.
- **Projection basis:** default per-person rate = the **latest full-month run-rate** (`projPerPerson()`), ≈120 msgs/person/mo from June. The Overview projection and the Forecast ramp both use this so they agree; the Forecast slider lets you stress-test it (June was a heavy month, so it's on the optimistic end).
- **Charts** are all hand-rolled inline SVG (no chart library) for portability. Helpers: `el()`, `svg()`, `donut()`, `darkText()` (darkens light slice colors for legibility as legend text). Tabs render lazily and pre-warm for printing.

## Verifying changes without a browser

The scripts run headless, but the dashboard JS needs a DOM. To catch runtime errors after editing the template, run it against a minimal DOM shim (this pattern was used throughout the build):

```js
// node -e '...'  — eval the template's last <script> with a fake document/window,
// stub querySelector to return objects with innerHTML/textContent/value/appendChild/setAttribute,
// then call draw("overview"), draw("trends"), ... and confirm no throw.
```
Also worth doing after any template edit: extract the last `<script>` block and `node --check` it for syntax.

## Caveats to state when presenting

- Topic/phase classification is **keyword-based and adjustable** — directional, not audited.
- ROI value rests on **time-saved assumptions**, not invoices. The ratio is lopsided enough (cost ≈ a rounding error vs. value) that it survives heavy discounting.
- June is a **partial month**; it is shown at full-month run-rate, which is on the high side.
